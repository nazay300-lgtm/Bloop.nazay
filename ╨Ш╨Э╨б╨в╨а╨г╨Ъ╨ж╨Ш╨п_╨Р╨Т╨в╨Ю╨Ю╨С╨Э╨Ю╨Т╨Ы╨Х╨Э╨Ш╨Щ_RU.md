# Bloop 1.0.0 Beta: настройка автоматических обновлений

Эта сборка подготовлена под Windows NSIS installer и `electron-updater`. Сам механизм обновления уже подключён в коде, но публикация не заработает, пока вы не укажете свой GitHub-репозиторий и не выпустите первый релиз. В этой копии `YOUR_GITHUB_USERNAME` намеренно оставлен как заглушка: чужой аккаунт угадывать было бы странным способом разработки.

## 1. Создайте репозиторий релизов

1. Войдите в GitHub и создайте репозиторий с именем `Bloop`.
2. Для простого старта сделайте его публичным. Не загружайте туда личные данные пользователей, токены, ключи или историю переписок.
3. Загрузите исходники Bloop в репозиторий.
4. Откройте `package.json` и замените `YOUR_GITHUB_USERNAME` в секции `build.publish` на ваш GitHub username. Если репозиторий называется иначе, поменяйте и `repo`.

Пример настройки:

```json
"publish": [
  {
    "provider": "github",
    "owner": "ВАШ_GITHUB_USERNAME",
    "repo": "Bloop",
    "releaseType": "prerelease"
  }
]
```

Вместо `ВАШ_GITHUB_USERNAME` должен стоять настоящий username, без `@`.

## 2. Установите зависимости

Установите Node.js LTS. В PowerShell откройте папку проекта и выполните:

```powershell
npm install
```

Эта команда установит `electron-updater` и синхронизирует `package-lock.json` с `package.json`. После изменения зависимостей не используйте старый lock-файл без обновления.

## 3. Создайте токен для публикации

Для публикации релизов нужен GitHub token с правом создавать/изменять Releases в вашем репозитории. Используйте минимально необходимые права и не вписывайте токен в исходный код, `package.json` или файлы проекта.

В PowerShell задайте токен только для текущего окна:

```powershell
$env:GH_TOKEN = "ВАШ_GITHUB_TOKEN"
```

Не отправляйте этот токен друзьям и не коммитьте его в Git.

## 4. Соберите установщик

```powershell
npm run dist
```

Установщик появится в папке `dist`, обычно под именем вида `Bloop-Setup-1.0.0-beta.0.exe`. Это установщик NSIS, а не прежний portable EXE. Первый раз друзья устанавливают приложение именно этим файлом.

## 5. Опубликуйте релиз

Для первой публикации и каждой следующей версии используйте:

```powershell
npm run release:win
```

Команда собирает Windows installer и публикует артефакты в GitHub Releases. Не публикуйте новую сборку с тем же номером версии, что и предыдущая.

Перед следующим релизом увеличьте `version` в `package.json`, например:

- `1.0.0-beta.0` — первая бета;
- `1.0.0-beta.1` — следующая бета;
- `1.0.0` — стабильный выпуск;
- `1.0.1` — исправления после стабильного выпуска.

После изменения версии выполните `npm install`, затем `npm run release:win`. GitHub Release должен содержать установщик и созданные electron-builder метаданные обновления, включая `latest.yml`. Не удаляйте эти файлы из релиза.

## 6. Как обновление выглядит у друзей

1. Друг один раз устанавливает Bloop через NSIS installer.
2. Приложение проверяет обновления при запуске и при открытии раздела «Настройки → Обновления».
3. Если версия доступна, Bloop скачивает её в фоне и показывает прогресс.
4. После загрузки обновление применяется при выходе из приложения. При следующем запуске открывается новая версия.

Настройки и данные пользователя должны храниться в `app.getPath('userData')`, а не рядом с исполняемым файлом. Не удаляйте папку данных при обновлении. В текущем проекте Electron сохраняет пользовательские данные отдельно; всё же перед массовой раздачей проверьте обновление на тестовом профиле.

## 7. Как добавлять историю изменений

В `renderer.js` найдите массив `BLOOP_RELEASES`. Для каждого релиза добавляйте объект с уникальным `id`, отображаемой версией, датой/подписью, кратким описанием и списком `changes`. В интерфейсе «Настройки → Обновления» версии будут прокручиваться по горизонтали, а описание выбранной версии показываться ниже. Список релизов в UI не загружается автоматически из GitHub: его нужно дополнять при выпуске версии.

## 8. Проверка перед рассылкой друзьям

- Установите предыдущую версию на отдельный тестовый компьютер.
- Опубликуйте версию с увеличенным номером.
- Запустите старую версию и проверьте, что она находит и скачивает новую.
- Перезапустите приложение и проверьте номер версии, контакты, настройки и историю.
- Проверьте установку на компьютере без Node.js и без исходников.
- Убедитесь, что Windows Firewall не блокирует локальные подключения Bloop.

Установщик без цифровой подписи может вызывать предупреждения Windows SmartScreen. Автообновление не заменяет проверку качества и не гарантирует, что звонки проходят через любой интернет-маршрутизатор.

## Важно про звонки

В проекте реализованы WebRTC-звонки, групповые приглашения и обмен медиа, но кодовая проверка не равна реальному тесту между двумя компьютерами. Перед объявлением полностью рабочей беты проверьте входящий звонок, принятие/отклонение, микрофон, камеру, демонстрацию экрана, завершение вызова и повторный вызов на двух устройствах. В этой версии не настроен собственный TURN-сервер; за пределами одной LAN/VPN-сети отдельные типы NAT могут мешать соединению.
